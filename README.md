# orchestra

The proposed stack is **Orchestrator for multi-agent coordination, Git worktrees for isolated parallel development, Python 3.12+ for the integration controller, SQLite for the persistent merge queue and transaction-based locking, and native Git for three-way merging and conflict detection**. Codex, Claude Code, Qwen, and DeepSeek operate as independent coding harnesses, each assigned its own branch and worktree. AI-assisted conflict resolution is delegated to a dedicated agent, while project-specific tests, linting, type checking, and builds serve as integration quality gates. A Next.js dashboard can be added later for monitoring, but the initial architecture should remain lightweight without Redis, Kafka, Kubernetes, or vector databases.

The **first actual integration on day one** should be a minimal end-to-end workflow connecting worker completion events to a persistent merge queue. When a worker finishes, the coordinator captures its task ID, branch, exact commit SHA, and changed files, then stores an integration job in SQLite. A single integration controller acquires an exclusive lock, checks out the designated integration worktree, merges the submitted commit, runs the project's validation commands, and records the outcome. Initially, use two test workers modifying separate files to verify successful integration, followed by two workers modifying the same lines to deliberately trigger a merge conflict.

Once that basic pipeline works, introduce an **AI conflict-resolution agent** that receives only the conflicting files, Git diffs, shared base, and relevant task specifications instead of entire conversation histories. The resolver reconciles both implementations inside the integration worktree, after which the controller reruns validation before accepting the merge. This creates a durable, restart-safe foundation for autonomous parallel development. We will provide worker orchestration, worktree management, and AI-assisted conflict-resolution capabilities; the serialized merge queue, integration controller, automated validation policy, and recovery mechanisms are the custom components that need to be built.
